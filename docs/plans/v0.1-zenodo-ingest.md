# MESS-datasets v0.1 — Zenodo Ingest

_Status: draft, authored 2026-04-20. Read `docs/plans/README.md` first
for the cross-repo strategy and scope rationale._

## Goal

Ship the first concrete release of MESS-datasets by ingesting a
solid coverage tier of MES-relevant research datasets from Zenodo,
proving the unified-schema + entity-linking pipeline end-to-end. Split
into two tags:

- **`v0.1.0-pilot`** — ~100 records. Validates the pipeline on a
  curated, human-reviewed set. Entity-linking precision/recall
  measured against a hand-labeled ground truth.
- **`v0.1.0`** — scale to ~500–1000 records covering the full MES
  domain. Entity-linker applied at scale; low-confidence records
  surfaced explicitly rather than silently excluded.

Figshare lands as v0.2. Dryad, OSF, and other sources are additive
behind the same schema.

## Scope

**In-scope for v0.1.0-pilot:**
- Zenodo records matching the MES search-term vocabulary (§3).
- Metadata + license + file manifest + slug crosswalks per record.
- Raw Zenodo API responses cached under `data/zenodo/raw/` for
  reproducibility (JSON only; no bulk file downloads).
- A hand-labeled 100-record ground-truth slice used to measure
  entity-linker precision and recall.

**Deliberately out-of-scope for v0.1:**
- Downloading dataset files themselves (metadata and download URLs
  only). Bulk-file storage is a separate deployment concern — see
  §8 of `docs/plans/README.md`.
- Dataset-to-patent linkage. Lives in MESS-patents when that repo
  ships its first release.
- Dataset-to-Zenodo-community tagging. Deferred; current Zenodo does
  not yet have a curated MES community.

## Inputs

- `search-terms.yaml` — the MES search vocabulary (see §3).
- Pinned MESS-Parameters submodule — supplies the 687 slugs that
  `mess_entities.parameter_slugs` and `.material_slugs` are
  validated against.
- Zenodo REST API — `https://zenodo.org/api/records`. Authenticated
  requests (60 req/min) via `ZENODO_TOKEN` in `.env`.

## Outputs

```
data/zenodo/
  raw/<record_id>.json             raw API response per record
  datasets-rich.json               canonical per-record payload, schema-validated
  crosswalk-by-slug.json           inverse index: slug → [record_ids]
  DATASHEET.md                     provenance, license, limitations
  entity-linker-eval.md            precision/recall against ground truth
data/mess-parameters-lock.json     upstream vocabulary pin + coverage stats
schemas/dataset.schema.json        canonical Dataset shape (§5)
schemas/crosswalk.schema.json      shape for inverse-index artifacts
```

## 1. Search-term vocabulary

Conservative to start — precision over recall for v0.1.0-pilot.

`data/zenodo/search-terms.yaml`:

```yaml
version: "v0.1"
last_reviewed: 2026-04-20
primary_terms:
  - "microbial fuel cell"
  - "microbial electrolysis cell"
  - "microbial electrochemical"
  - "bioelectrochemical system"
  - "bioanode"
  - "biocathode"
  - "MFC"           # acronym, expect false positives; see exclusions
  - "MEC"           # same
  - "exoelectrogen"
  - "Geobacter"
  - "Shewanella"
secondary_terms:     # queried but require corroborating signal from primary
  - "coulombic efficiency"
  - "bioelectricity"
  - "bioelectrochemistry"
  - "biofilm electrode"
exclusions:          # filtered out of Zenodo results
  - "MFC receptor"   # "Major Facilitator" protein family — biomedical false positive
  - "MEC-1"          # cancer cell line — also biomedical
  - "metal fuel cell"  # distinct technology
  - "solid oxide fuel cell"
date_range:
  from: "2010-01-01"
  to: null           # open-ended; capture recent deposits
```

Start with 100 records matching `primary_terms`, minus `exclusions`,
minus any record in the date range where the abstract mentions none
of the MES-relevant keywords after secondary-term co-occurrence
filtering. Manual review before committing to rich.json.

## 2. Fetcher pipeline

Mirrors MESS-Materials' script layout:

```
scripts/
  _common.py                       slug derivation, .env loading,
                                   MESS-Parameters path resolution
  fetch-zenodo.py                  paginated API fetch + raw cache
  link-entities.py                 rules + LLM hybrid; emits crosswalks
  assemble-rich-json.py            joins raw + crosswalks → datasets-rich.json
  eval-entity-linker.py            precision/recall against ground truth
```

`fetch-zenodo.py` semantics:
- Queries `/api/records` for each primary term, combines result sets.
- Deduplicates by Zenodo record ID.
- Respects the 60 req/min rate limit; uses `retry-after` when
  throttled.
- Records fetch timestamp per record for provenance.
- Writes raw JSON under `data/zenodo/raw/<record_id>.json`.
- Applies exclusion-keyword filter as a post-fetch pass (so the raw
  cache is inclusive; filtering is reproducible from cached data).

`link-entities.py` semantics:
- Input: raw record (title + description + keywords).
- Step 1 — **rule pass**: dictionary match against MESS-Parameters
  slug vocabulary + a hand-curated synonym list per slug.
  Deterministic, fast, high precision.
- Step 2 — **LLM pass** (only on records where the rule pass finds
  ≥1 slug): prompt an LLM with the record text + the MESS-Parameters
  vocabulary + instructions to add confident additional matches and
  flag uncertainty. Records with 0 rule-pass hits do **not** go to
  the LLM (keeps cost bounded; also the precision of LLM-only runs is
  not good enough to ship without a rule anchor).
- Step 3 — **confidence-tier assignment**:
  - Rule-pass match only, single slug → `medium`.
  - Rule-pass match for ≥2 slugs with consistent co-occurrence (e.g.
    "carbon cloth" + "power density" in the same sentence) → `high`.
  - LLM-only addition without rule corroboration → `low`.
- Step 4 — **LLM self-consistency check**: run the LLM pass twice at
  temperature 0; discard matches that differ between runs. Cheap
  regularizer against LLM hallucinations.
- **Standalone linker in this repo, not routed through MESS-Parameters'
  Nougat + Groq pipeline.** The two tasks are different enough that
  reuse would force the wrong tool: MESS-Parameters' pipeline is built
  for PDF-to-structured-values extraction over 20-page papers; this
  repo needs vocabulary-constrained classification over ~200-word
  Zenodo abstracts. Nougat is irrelevant (no PDFs), and the Groq
  prompts designed for paper extraction don't apply. A ~100-line
  Python matcher + a tightly-schema-constrained Groq call for
  ambiguous cases is the right size.
- **What IS shared upstream:** the synonym dictionary mapping slug →
  aliases. Lives once in MESS-Parameters (proposed addition) and is
  consumed by both MESS-datasets and the future MESS-patents linker.
  One file, one source of truth for vocabulary; no pipeline
  coupling.

## 3. Ground-truth evaluation

Non-negotiable for v0.1.0-pilot. 100 hand-labeled records covering:
- 70 positive records (clear MES relevance, at least one slug)
- 30 negative records (Zenodo search hits that are not MES — e.g.
  fuel-cell records about SOFCs, biomedical MFC false positives)

Labeled by hand before running the linker. The linker is scored:
- Precision = linked-slugs that are correct / total linked-slugs.
- Recall = linked-slugs that are correct / ground-truth slugs.
- Per-confidence-tier breakdown.
- Target for v0.1.0-pilot: precision ≥ 90% on `high` tier, ≥ 70%
  on `medium`, recall ≥ 60% overall. Miss the target → scope back
  to higher-confidence-only shipping, document in DATASHEET.

## 4. License handling

Per-record license is **required** in the output schema. Zenodo
records carry an SPDX-compatible license identifier in their metadata
(`metadata.license.id`). Pipeline rules:

- Records without a license field → excluded from `datasets-rich.json`
  (count logged to DATASHEET as "license-missing-excluded").
- Non-CC records allowed in v0.1, but flagged clearly: the schema
  emits `license.spdx_id` verbatim so downstream UI can filter if
  needed.
- Consumer UI (messai-ai) must display attribution text per record.
- No relicensing — MESS-datasets publishes under CC-BY-4.0 for its
  own derived artifacts (crosswalks, rich.json envelopes), but every
  record inside carries its upstream license verbatim.

## 6. CI invariants

Enforced in `ci/validate.yml` on every PR:

- Every record in `datasets-rich.json` validates against the schema.
- Every `parameter_slugs[*]` and `material_slugs[*]` exists in the
  pinned MESS-Parameters submodule.
- Every record has a non-null `license.spdx_id`.
- `data/mess-parameters-lock.json` matches the submodule pin at
  build time.
- Ground-truth eval (§3) must be present and meet thresholds for the
  release tag to proceed.

## 7. Pipeline validation checklist — v0.1.0-pilot

Cannot tag until every item passes:

- [ ] 100 records in `datasets-rich.json`, all schema-valid.
- [ ] Per-record license present; distribution summarized in DATASHEET.
- [ ] Entity-linker eval report committed with precision/recall
      numbers and per-tier breakdown.
- [ ] `search-terms.yaml` version recorded in `mess-parameters-lock.json`
      so downstream consumers can detect search-vocabulary drift.
- [ ] 5 spot-check anchors — known MES datasets whose expected slug
      extraction is documented — round-trip through the pipeline
      correctly.
- [ ] `DATASHEET.md` written covering: source URL, license distribution,
      excluded-counts, entity-linker version, known limitations
      (e.g. "Zenodo records without MES-relevant keywords in titles
      are missed — ~X% recall gap flagged by eval").

## 8. Consumer impact (messai-ai)

Lands with the v0.1.0 gitlink bump after pilot validates:

- Declare MESS-datasets as a submodule pinned to v0.1.0 tag.
- New `scripts/generate-dataset-fixtures.ts` splits
  `datasets-rich.json` + `crosswalk-by-slug.json` into per-slug
  fixtures under `apps/web/public/data/datasets/<slug>.json`.
- New `getDatasetsBySlug(slug)` service alongside the existing
  `getParameterBySlug` / `getMaterialBySlug`.
- New `RelatedDatasetsSection` component on the parameter detail
  page: "Datasets mentioning this parameter (N)" with per-record
  title, creators, DOI link, and per-record attribution.
- Rollback lever: `NEXT_PUBLIC_DATASET_DATA=off`.
- Fixture volume (~500 slugs × few datasets each) remains in
  static-fixture scope. If v0.2+ (Figshare) pushes us past a
  reasonable static fixture size, that is when `MaterialProperty`
  and `DatasetReference` Prisma tables land with a server-side
  join — see §5 open decision in the wider strategy doc.

## 9. Timeline

- **Week 1** — scaffolding, search-term curation, 100-record
  manual review, ground-truth labeling.
- **Week 2** — fetcher + entity linker (rule pass), eval
  infrastructure, DATASHEET draft.
- **Week 3** — LLM pass integration (reuse MESS-Parameters pipeline
  if aligned; else standalone). Eval; precision/recall pass.
- **Week 4** — tag `v0.1.0-pilot`; messai-ai consumer PR opened.

v0.1.0 (500–1000 records) adds ~2 weeks on top as a second pass
once the pilot validates.
